<objective>
Build the barrier-state detection core: a reference-frame edge-matching classifier plus a dwell-gated finite state machine.

Purpose: Deliver BARRIER-01 (report barrier state), BARRIER-02 (track CLOSED→OPENING→OPEN→CLOSING) and BARRIER-03 (exactly one event per opening) as pure, fully testable modules.

This plan deliberately does NOT touch real recordings, the live feed, or `main.py`. The classifier and FSM are exercised with synthetic scenes so the phase can be executed and reviewed before any on-site recording session exists. Wiring and empirical validation are Plan 02-02.

Critical constraint inherited from `02-CONTEXT.md` D-04 and `02-RESEARCH.md`: the source is a ~1.5 fps single-frame snapshot feed, so a 2-5s opening yields only 3-8 frames. Therefore this phase implements **state classification with dwell confirmation**, never velocity-based transition tracking.
</objective>

  <name>Task 1: Dwell-gated barrier FSM</name>
  <files>
    src/detect/__init__.py
    src/detect/fsm.py
    tests/test_barrier_fsm.py
  </files>
  <action>
    Create the package marker `src/detect/__init__.py` (empty) and `src/detect/fsm.py`.

    1. `class BarrierState(str, Enum)` with members `CLOSED`, `OPENING`, `OPEN`, `CLOSING`, and a sentinel `UNKNOWN` that the FSM must never settle into.
    2. `@dataclass(frozen=True) class TransitionEvent`: fields `from_state`, `to_state`, `at: float`, `emits_event: bool`. `emits_event` is True ONLY for `OPENING -> OPEN` — this is BARRIER-03, exactly one open event per opening.
    3. `@dataclass(frozen=True) class Observation`: `state: BarrierState`, `confidence: float`, `detail: str = ""`. The detector only ever reports CLOSED, OPEN or UNKNOWN; the FSM derives the intermediate states itself.
    4. `class BarrierFSM.__init__(self, dwell_open: int = 2, dwell_closed: int = 4, clock=time.monotonic)`, starting in `CLOSED`.
    5. `update(self, observation) -> list[TransitionEvent]`. The pending counter is reset to 0 on EVERY state change and whenever an observation affirmatively matches the committed state. An `UNKNOWN` observation is **neutral**: it neither commits nor discards evidence.
       - observation equals the current state → reset pending to 0, return `[]`;
       - observation is `UNKNOWN` → leave pending unchanged, return `[]`. This matters at ~1.5 fps: a 2 s opening is only ~3 frames, so one ambiguous frame must NOT throw away accumulated evidence. UNKNOWN means "no new information", never "information against";
       - otherwise (an affirmative opposite state) increment pending and commit when the threshold for that direction is met:
         - `CLOSED -> OPENING` after **1** OPEN sample (`emits_event=False`);
         - `OPENING -> OPEN` after `dwell_open` FURTHER samples (`emits_event=True`). With `dwell_open=2` that is **3 total samples of OPEN evidence** (1 to reach OPENING + 2 more) ≈ 2.0 s at 1.5 fps. Keep `dwell_open=2`; demanding more would make a fast opening undetectable with a 3-frame budget;
         - `OPEN -> CLOSING` after **1** CLOSED sample (`emits_event=False`);
         - `CLOSING -> CLOSED` after `dwell_closed` FURTHER samples (`emits_event=False`);
         - reversal while `OPENING` → back to `CLOSED` after **1** CLOSED sample, no event; reversal while `CLOSING` → back to `OPEN` after **1** OPEN sample, **no new event** — the anti-duplicate rule for BARRIER-03.
       - Because returning to CLOSED needs `closed_dwell` (default 4 ≈ 2.7 s), flapping cannot manufacture a second opening.
    6. The clock is injectable and used only to stamp `TransitionEvent.at`, never for control flow, so tests never sleep.
    7. BARRIER-01 names a third condition «частично открыт». At ~1.5 fps a partially raised arm is not reliably separable from either end state, so it is represented by the transitional `OPENING` / `CLOSING` states rather than by a distinct observation. Record this interpretation explicitly in `02-01-SUMMARY.md`; do NOT invent a `PARTIAL` observation the classifier cannot support.

    Create `tests/test_barrier_fsm.py` (no network, no recordings, fake clock) asserting: the CLOSED→OPENING→OPEN order; exactly one `emits_event=True` per opening; extra OPEN samples while already OPEN emit nothing; an OPEN→CLOSING→OPEN wobble emits no second open event; UNKNOWN never commits; `closed_dwell` must elapse before returning to CLOSED.
  </action>

<task type="auto">
  <name>Task 2: Reference-frame edge-matching classifier</name>
  <files>
    src/detect/barrier.py
  </files>
  <action>
    Create `src/detect/barrier.py`. This module stays pure: it may import `cv2`, `numpy` and `src.detect.fsm`, but MUST NOT import anything from `src.capture` (no network, no FrameBuffer, no settings) so it stays unit-testable.

    1. `WORK_SIZE = (320, 180)` (width, height) — the single working resolution. Reference maps are stored at exactly this size (RESEARCH.md "Грабли реализации": storing 1280×720 references bloats the repo and breaks the comparison).
    2. `def mean_brightness(frame) -> float` — mean of the grayscale, downscaled; picks the lighting bucket.
    3. `def preprocess(frame) -> np.ndarray` — BGR→GRAY (`cv2.cvtColor(..., cv2.COLOR_BGR2GRAY)`), `cv2.resize(frame, WORK_SIZE, interpolation=cv2.INTER_AREA)`, `cv2.GaussianBlur(gray, (3, 3), 0)`, then `cv2.Canny(gray, 60, 160)`, returning a `uint8` 0/255 edge map. The edge representation is what makes classification survive day/night and IR switching.
    4. `LIGHT_BUCKETS = ("day", "night")` and `def bucket_for(brightness: float, threshold: float = 60.0) -> str`.
    5. `@dataclass(frozen=True) class ReferenceSet` — per `camera_id`, per bucket, a `closed` and an `open` edge map plus the two ROI rectangles `[x, y, w, h]`. Provide `save(dir)` / `load(dir)` via `cv2.imwrite` / `cv2.imread` so references commit as small PNGs. Validate on load that every map is exactly `WORK_SIZE` and raise a clear error if not.
    6. `class BarrierDetector.__init__(self, references: ReferenceSet, margin: float = 0.15, open_extent_ratio: float = 0.6)` and `def classify(self, camera_id: str, frame) -> Observation`:
       - preprocess, pick the bucket by brightness, crop the closed and open ROIs; **if no reference exists for that `(camera_id, bucket)`, return `Observation(UNKNOWN, detail="no_reference_for_bucket")` immediately** — never silently fall back to the other lighting bucket and never guess;
       - `d_closed` = fraction of pixels whose edges differ from the closed reference, `d_open` = the same against the open reference (boolean numpy comparison, not `cv2.absdiff` on images — cheaper and unambiguous);
       - `gap = abs(d_closed - d_open)`; if `gap < margin` return `Observation(BarrierState.UNKNOWN, ...)` — an ambiguous frame must never move the FSM;
       - otherwise the state is `argmin(d_closed, d_open)` mapped to `OPEN` / `CLOSED`;
       - **geometric corroboration**: inside the closed ROI run `cv2.connectedComponentsWithStats` on the edge map and take the largest component's height (`stats[:, cv2.CC_STAT_HEIGHT]`). When the classification is OPEN but that height is below `open_extent_ratio` of the ROI height (the arm is still horizontal), return `UNKNOWN` with `detail="geometric_mismatch"`. This is the specific guard that stops a passing vehicle from flipping the state.
    7. Debug logging with a `camera=<id>` prefix (project convention); never log raw frames.

    Do NOT add MOG2 in this plan. RESEARCH.md keeps it as an optional shadow/car filter, and a background model initialised while the arm is raised is actively harmful (RESEARCH.md "Отравление фоновой модели").
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recorded frame / live snapshot → detector | untrusted image data of unknown size and content |
| reference PNGs on disk → `ReferenceSet.load()` | files a human curated by hand; can be stale, mismatched or wrong-sized |
| config ROI values → detector | operator-supplied integers; out-of-range values must not crash the process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | `ReferenceSet.load()` | medium | mitigate | Validate every map is exactly `WORK_SIZE` and reject mismatches loudly; a wrong-sized reference silently destroys the comparison |
| T-02-02 | Denial of service | `preprocess()` | low | mitigate | Guard frame dimensions and non-empty input; a malformed snapshot must raise a named error, not hang the consumer thread |
| T-02-03 | Information disclosure | logging | low | mitigate | Log state, distances and `camera_id` only — never raw frame bytes or reference images |
| T-02-04 | Spoofing | reference selection by brightness | low | accept | A mis-selected day/night bucket degrades confidence; the `margin` guard turns that into UNKNOWN rather than a wrong state |

No credentials cross a boundary in this plan — the detector never touches the network. That is the point of keeping `src/detect/` free of `src/capture` imports.
</threat_model>
