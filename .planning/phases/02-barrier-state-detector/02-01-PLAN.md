<objective>
Prove the whole Phase 2 architecture end to end on one path, and deliver the signal layer that everything else expands from.

Build the thinnest complete vertical slice: a real JPEG frame on disk, read one at a time by `ReplaySource`, converted by `closed_ratio` into an illumination-normalized darkness number, and turned by `BarrierFSM.step` into a named state transition. Then harden that slice's two trust boundaries — undecodable frames and out-of-bounds ROI geometry — with named errors.

Purpose: this is the tracer. If the frame-buffer-free generator contract, the normalized-ratio signal, or the FSM seam is architecturally wrong, it fails now, after one commit, rather than after three plans have built on it. Everything in 02-02 and 02-03 is horizontal expansion from this proven slice.

Output: `src/detect/replay.py`, `src/detect/barrier.py`, `src/detect/fsm.py`, a deterministic synthetic-clip test factory in `tests/conftest.py`, and the first green end-to-end test in `tests/test_barrier_detector.py`. No live stream, no credentials, no ffmpeg binary, no `FrameBuffer` in the path.
</objective>

## Plan-visible decisions (this plan records them; later plans inherit them)

1. **No regular-package marker for `src/detect/`.** `src/capture/` has none, `pythonpath = .` in `pytest.ini` already makes `src.detect.*` importable, and every existing test imports `src.*` successfully under that arrangement. Adding a marker file for one new directory would split the codebase into two package conventions for zero functional gain. `src/detect/` stays a namespace package exactly like `src/capture/`. The acceptance check is behavioural (the three modules import; exactly three new files appear under `src/detect/`), not a marker-file existence check.

2. **No `pytest-timeout` dependency.** RESEARCH's Pitfall 1 failure mode is a hang, not a failure, and RESEARCH recommends `pytest-timeout`. This plan does not add it. Reasons, in order: RESEARCH's own Package Legitimacy Audit concludes "No new packages are required for Phase 2"; the project's YAGNI ladder settles on the platform's native feature before adding a dependency; and `pytest-timeout` is `[ASSUMED]`, so adding it would force a package-legitimacy human checkpoint for a test-only convenience. The compensating controls are (a) `faulthandler_timeout = 30` added to `pytest.ini` here — verified during planning to dump tracebacks for a stuck test (diagnostic visibility only; it does not abort the run), and (b) making the hang-guard test in 02-03 structurally incapable of hanging by construction rather than by timeout. If a real hang appears during execution, adding `pytest-timeout` becomes a concrete, evidence-backed decision and its legitimacy checkpoint is then worth paying for.

3. **The RESEARCH `ReplaySource` snippet must not be copied verbatim.** It carries two defects: its initializer assigns a file list while its iterator reads a clip-directory attribute that is never assigned, and it has no guard for a `None` return from `cv2.imread`. Task 1 fixes both.

4. **No live capture anywhere in this phase.** Corporate group policy blocks the system `ffmpeg` binary on this host, and there are no privratnik.net credentials. `cv2` bundles its own FFmpeg build, which is why decoding still works offline, but no task in this plan may depend on the live stream succeeding. Real footage enters only through the operator-gated checkpoint in 02-03.

<flagged_assumptions>
The spec-less edge probe returned `unclassified`/`unresolved` for all four phase requirements, so no edge row was auto-resolved. These are surfaced, not silently dropped, and none is auto-resolved:

- **A-01 (BARRIER-01, unresolved).** *"Reports whether the barrier is open, closed, or partially open."* The probe could not classify what separates a genuinely "partially open" report from a transient mid-sweep sample. This plan resolves the ambiguity deliberately: "partially open" is delivered as the two transit states OPENING and CLOSING of a four-state machine plus a derived boolean, never as a fifth persistent state — the reconciliation RESEARCH's Open Question 2 calls for. The residual unknown is threshold calibration, carried as the backstop truth in this plan's must_haves.
- **A-02 (BARRIER-02, unresolved).** *"Transitions between those states follow a defined state machine."* "Defined" could mean the four edges only, or the four edges plus a documented diagram. Neither is verifiable from requirement text alone; plan 02 asserts the four edges and their ordering as the acceptance criterion.
- **A-03 (BARRIER-03, unresolved).** *"One event per opening, no duplicates."* The probe could not determine whether "one event" is scoped per camera or per session, nor what the duplicate window is. Plan 02 asserts per-camera, per-opening-cycle, with edge-only emission and no wall-clock window.
- **A-04 (BARRIER-04, unresolved).** *"Resists false positives from shadows, a passing car, and lighting changes."* "Resists" has no measurable bound in the requirement text. Plans 02 and 03 assert it as a bounded ratio excursion that must not cross the release threshold, and as a frame-level degradation matrix, respectively. The residual unknown is whether real shadows behave like synthetic ones — this cannot be resolved without the operator's SC4 footage.
</flagged_assumptions>
