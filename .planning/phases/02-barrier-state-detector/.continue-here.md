<decisions_made>

- **Both failures share one root cause: the synthetic fixture discriminates too thinly.** Edge maps are sparse (~3% of pixels), so inter-class distances are small: measured gap is **0.0444 for a closed scene and 0.0374 for an open one** against a provisional `margin=0.02` — only ~1.9x headroom. Any scene variation falls inside the margin (failure 1); conversely a heavily noised frame need not become ambiguous, because noise raises both distances together while leaving their ordering intact (failure 2).
  This is a **fixture-quality** problem, not a detector-logic problem — `barrier.py` behaves correctly in both cases by refusing to guess. The remedy is a more discriminative fixture, not a looser margin.
- **Fixture options, in order of preference:** (a) add background texture so edges are denser and inter-class distances grow; (b) narrow the ROIs onto the region where the two orientations differ most; (c) thicken the arm. Prefer (a) — it also makes the fixture more like real footage, which is never edge-free.
- **`margin=0.02` is explicitly provisional.** Per `02-RESEARCH.md`, margin and dwell are calibrated against real recordings in plan 02-02. Do not raise it to make synthetic tests pass.
- **Generator bug found and fixed (remember it):** `np.linspace(0, 20, 720)[:, None]` has shape `(720, 1)`, so adding it to a scalar produced a **1-pixel-wide** frame and Canny found zero edges everywhere. Fix: `np.full((720, 1280), brightness) + gradient`.
- **A test expectation was corrected, not the code:** an unknown camera returns `UNKNOWN / no_reference_for_bucket` rather than raising — that is the intended "never guess" behaviour.
</decisions_made>
